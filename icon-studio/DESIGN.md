# dsh-icon-library · 设计

## 一句话

项目级图标**身份 + 语义注册表**：每个图标只有名称、应用规则、图形三件事；
名称是 agent 和业务代码唯一的指代，图形只能整份替换。

## 录入：两个入口，没有第三个

1. **从代码导入**：扫描 UI 源码的内联 `<svg>`，同一形状归一组；给组起唯一名称即入库，
   并把该形状在代码里的位置登记为一条**派生**。
2. **粘贴 SVG**：外部图形，直接入库。

代码里不写标记：派生就是"画着同一个形状"，由**几何签名**索引——颜色和线宽不参与
匹配，所以同一个形状在 A 处是 `#ff00ff`、在 B 处是 `#000ff0`，仍是同一个形状的两条派生。

## 入库：一个窗口，四个来源

粘贴、本地 `.svg`、远程供给库、AI 生成，打开的是**同一个** `AddIconDialog`：

| 来源 | 顶部那块 | 其余部分 |
|---|---|---|
| 粘贴 / 本地文件 | SVG 源码框 + 解析 | 预览、名称、应用规则、重名/同形提示 |
| 远程供给库 | 来源与许可、描边/实心切换 | 同上 |
| AI 生成 | 描述框、生成/重画、参考与穿帮提醒 | 同上 |

差别只在"图形怎么来"；预览、命名、规则、冲突检查、保存与派生索引全部共用。供给库来源
走 `library-import`（保留 `source` / `license` / `origin`），其余走 `save`。

## 供给：两个上游，一个浏览器

导入不是"两个入口"，而是一个供给库：两个上游并列，共用搜索、预览、选择与入库。

| 上游 | 规模 | 语义 | 许可 |
|---|---|---|---|
| Iconify | 276 集合（长尾） | 无，只有名字 | 各集合自带 |
| IconMCP | 58 集 / 7,745 图 | label + tags + set，可按含义搜 | MIT |

一个外部引用就是一个字符串，写法和库内名称一致：

```
lucide:trash            # Iconify：前缀就是集合 id
iconmcp-generic:trash   # IconMCP：前缀带集合
```

- 集合页只返回**裸名字**，`前缀:` 统一由客户端加（搜索返回完整 ref）——两处都加
  前缀就会出现 `iconmcp-generic:iconmcp-generic:plus`，一页图标全部取不到图。
- 集合卡片的许可行同时标出来源：`IconMCP · MIT · 141 个图标`；IconMCP 不提供
  `samples`，卡片预览按页每集补一次 `get_set`（format svg / limit 3），分批到达。
- 搜一次问两家：IconMCP 在前（按含义排序、容错、基础图形排在变体前），
  Iconify 补长尾；同名图形只留第一个。
- **只导 outline / solid**：IconMCP 的 duotone 写死 `#2D68FF`，破坏"单色、继承
  currentColor"。
- **画布按原始 `viewBox` 入库**（IconMCP 是 16），不塞进默认 24 画布——否则图形按
  2/3 大小画在角落。
- 导入即落盘：`source: "iconmcp:generic"`、`license: "MIT"`。供给是**导入时刻**的
  一次性取用，构建期不联网，`.icons.json` 之外没有运行时依赖。
- 上游的 label + tags 直接播种第一条应用规则（`Trash — delete, remove, bin`）；
  "什么时候别用"是项目知识，留给 `icon_annotate`。

### 入库：先确认，再写入

从供给库添加不是“点一下就进库”，而是先开一个确认面板：

- **名称**：预填图标自己的名字（`trash`，不是 `iconmcp-generic:trash`），可改；
- **应用规则**：预填上游知道的（IconMCP 的 label + tags），可改；Iconify 没有这份数据，
  就留空，不编造；
- **风格**：只有上游真的画了第二份才出现（outline / solid）。逐字比较两份图形，相同就
  不提供——否则会把线稿当实心导进来；
- 重名与同形冲突都留在面板里改，不关面板。

入库同时记 `origin`（上游 ref）。本地名字是用户的选择，`origin` 才是“这个图标已经在
库里”的凭据：重命名不丢来源，卡片也不会重复导入。

## 界面：两块，没有第三块

```
右侧栏「图标」
├─ 列表  网格预览 / 搜索（名称·应用规则）/ 导入·粘贴 / 拖拽排序 / 拖到聊天框落名字
└─ 详情  名称 / 应用规则 / 粘贴新 SVG 替换 / 撤销替换 / 删除
```

- 打开面板**永远落在列表**。
- **没有画布编辑器**：图形不靠画，靠粘贴。编辑器已从 `lib/client.js` 删除。
- **没有 `@` 提及**：对话里用 `<名称>` 指代（纯文本），例如 `<删除>`；拖拽落下的就是这个引用。
- 粘贴 SVG → **立刻弹命名面板**；名称必填、库内唯一，不填不保存。
- 图形与库里已有条目相同时，面板**展示已有的名称和应用规则**，一键打开它。

## 数据模型（`.icons.json`，IconifyJSON 对齐）

```jsonc
{
  "format": "dsh-icon-library",
  "width": 24, "height": 24,
  "icons": {
    "delete": {
      "body": "<defs>…</defs><path …/>",
      // left/top/width/height 省略时取顶层默认（0,0,24,24）
      "rule": "删除动作…",                                // 应用规则，选填
      "pointers": [{ "file": "src/a.tsx", "kind": "inline", "index": 0, "line": 3 }],
      "scannedAt": "…",                                     // 上次在工作区里找过引用
      "hash": "sha256:…",
      "createdAt": "…", "updatedAt": "…", "version": 1, "pushed": 1
    }
  },
  "updatedAt": "…"
}
```

- 顶层 `updatedAt` 是库的修订号来源：面板轮询带上它，未变化时只回 ~160 字节并跳过重渲染。
- `metadata.<name>.scannedAt` 记录"这个图形在 workspace 里查过引用"；为空只意味着要扫一次，
  扫过之后（哪怕没找到）不再每次打开都重扫，显式重新扫描除外。

- `note` 是 v1 字段，读入时迁移为 `rule`，写出只有 `rule`。
- `body` / `left` / `top` / `width` / `height` 即 IconifyIcon；其余字段是本库扩展。
- 没有 blob 文件、没有服务端 history：撤销是编辑会话内的内存缓冲。
- `pointers` 是同步目标：项目里画着同一形状的位置。

## 派生：粘贴即连线

粘贴的图形通常**来自项目本身**（从组件里复制出来的）。保存时：

1. 用**粘贴时的原始坐标**做几何签名（规范化会裁画布，不能用导出后的 SVG 比对）；
2. 扫描 workspace 的独立 `.svg` 与代码里的内联 `<svg>`，签名相同即登记为指针；
3. **新建图标只登记、不改代码**；**编辑（version > 1）才原地重写**所有指针。

指针重写只替换 `<svg>…</svg>` 块，代码其余部分逐字节不动。

## 同步：没有手工人肉步骤

```
打开详情 ──▶ 体检（只读）：补指针 + 报同形条目
保存/替换 ──▶ 自动重写所有指针（构建期内联的 @asset 拷贝同样重写）
撤销替换 ──▶ 恢复图形并重新推给所有指针
```

- 面板上没有推送 / diff / 全部推送入口，同步不是用户的动作。
- 扫描只收**方形画框**：`viewBox` 宽高相等（或 `width`=`height`）才算数；宽高不等、
  以及没声明画布的 SVG（隐式 300×150）一律不提供，被排除的数量显示在扫描页。
- 扫描与重写只覆盖 vibe-coding 的 UI 源码（`.tsx` `.jsx` `.vue` `.svelte` `.astro` `.html`
  `.svg`）；`test/`、`fixtures/`、`mocks/`、`stories/`、`docs/`、`*.test.*` 一律排除。
- 判定按几何签名（形状），不是字节：重排格式、换缩进不算差异。

## AI 生成：一条提示词，一张草稿

面板 `⋯` 菜单里的「AI 生成图标」不是一条独立的入库通道：

1. 先读当前库的风格——画框尺寸、最常见的 `stroke-width`、以填充还是描边为主、常用
   图元，外加 2–3 个真实图标作为示例；
2. 再去供给库（IconMCP → Iconify）找 2–3 个**同类图标当构图参考**。它们只进提示词，
   并明确要求"不要复制路径"；离线时跳过这一步，照样出图；
3. 模型按"本库风格 + 这些构图"画一张 SVG，同时给出名称与规则；
4. **先校验再回填**：方形画框、只许 `currentColor`（写死颜色直接拒）、只用几何图元、
   元素 ≤ 12；不合格当场拒绝并说明原因，什么都不写；
5. 生成后先给用户看**预览 + 几何提醒**（描边互相穿过 = 两个形状可能叠在一起），
   可以带着"哪里不对"重画一次；
6. 满意的草稿进入**同一个入库对话框**（名称与规则可改），保存路径与其他图标完全一致。

AI 只负责"画"：身份、应用规则、去重、派生索引仍由原有流程把关。

## 派生面板

详情页的「{n} 处派生」展开的是**代码里那一处真实画出来的样子**：

- 每条派生一个缩略图——读的是源码里的 SVG 块本身，不是库里的走形图；
- 只给缩略图和位置：`文件:行`，独立 `.svg` 文件则只给路径（文件里没有"第几行"这回事）。
  颜色与线宽不再单独标注——预览本身就是那处的真实渲染，重复一遍是噪音；
- 无法定位的派生（代码改动、文件移动）不显示空框，只计数并提示重新扫描。

派生没有独立的记录：它就是代码里的那段 SVG。改 raw 只改几何属性，派生各自的颜色与
线宽一个字节都不动。

## Agent 契约

| 工具 | 语义 |
|---|---|
| `icon_list` | 按名称与应用规则检索；返回截断的应用规则，不返回 SVG |
| `icon_get` | 取一个图标：完整 SVG + 完整应用规则 + 用法约束 |
| `icon_save` | 名称必填；同名覆盖，异名同图被拒绝并指回已有名称 |
| `icon_annotate` | 只改应用规则，不动图形 |

注入给 agent 的规则同样如此：先检索、按含义选择、找不到就明说；不静默换公共图标。

## 形状身份：只看内部代码

- 判定一个形状 = 内部路径与绘制属性 + **画框比例**；
- 同一内部代码放在 16/24/48 的方形框里，是同一个图标；放到 24×48 的框里，不是；
- 绝对尺寸（`width`/`height`、viewBox 的具体数值）不属于身份；
- 替换代码时只替换 `<svg>…</svg>` 内部的内容，各位置保留自己的画布与尺寸属性。

## 不变量

1. 名称必填且唯一；没有 `icon-<n>` 兜底。
2. 规则选填；缺规则只降低选图准确度，不影响图形。
3. 同一 `body + viewBox` 哈希只有一个入库位置；重复粘贴指向先入库的那一份。
4. 派生 = 几何签名匹配的位置；颜色、线宽、绝对尺寸都不影响匹配，换画法才脱链。
5. `.icons.json` 是唯一不可重建的数据；其余皆可由它派生。
6. 替换图形不清空应用规则：`save` 不传 `rule` 表示「保持原样」，显式 `''` 才清空。
   规则是项目知识，图形只是它的载体。
