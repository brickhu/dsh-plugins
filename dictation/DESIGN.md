# DESIGN · 英文听写 / English Dictation

## 当前产品方向（2026-11，v0.48）

**源与等级解耦。** 上一版把等级绑在源上（News in Levels 同一篇故事 L1/L2/L3 各发一条），结果列表里同名文章重复，话题也只有新闻。现在源只提供"原文 + 话题 + 许可证"，等级由用户在**添加那一刻**决定：点行尾的 `+` 弹窗选 A1–C2（默认是 profile 里记住的"我的等级"），确认后 AI 改写并入库——同一篇原文只对应所选的那一级，话题靠多源组合拉宽。页面顶部没有等级选择器：等级不是筛选条件，而是"这一篇属于我哪一级"的记录。

**源的选择标准是硬约束：国内可直连 + 许可证允许改写。** 这两条一起把大部分"看起来很适合"的源都排除了：

- 被墙：Wikipedia / Simple Wikipedia / Wikivoyage / On this day / VOA / Global Voices / The Conversation（上海出口实测超时）。
- 只有标题没有正文：NIH（403）、Gutenberg（503）、NSF 正文页（"not available in your region"）。
- 许可证禁止改编：The Guardian（条款限制 "edit or adapt"）、The Conversation / ProPublica / Mongabay / Quanta / Undark（CC BY-ND / BY-NC-ND）。
- 抽不出正文：UN News（All rights reserved）、European Commission（只有 ~35 词摘要）。

留下来的 7 个源：NASA、NOAA、NIST（美国政府公共领域）、WHO（CC BY-NC-SA 3.0 IGO）、Our World in Data、PLOS ONE、Frontiers（CC BY 4.0）。它们一起覆盖太空/天文、海洋/气候、科技/网络安全、健康、社会/经济、科学/医学、心理/行为——话题比原来的单一新闻源宽，代价是暂时没有体育、旅行、娱乐和实时世界新闻。

**列表是 RSS 阅读器式的时间线，不是一个轮询窗口。** 每次轮询每源最多抓 20 条，`sources.json` 把新 URL 合并为未读、刷新已有 URL 的标题/摘要但保留已读状态，整条时间线保留 45 天 / 最多 1200 条、按发布时间倒序。轮询本身缓存 10 分钟（避免每次开页都打源站），但页面读到的是完整历史；刷新按钮必须带 `force=1` 才会合并新文章——之前不带 force，按钮等于把同一份缓存再渲染一遍。打开原文预览或生成练习会把文章标记为已读：未读标题前一个小蓝点，已读标题变灰，和 RSS 工具一致。**时间线文件里只有元数据**（标题、URL、240 字以内的摘要、时间、许可证、已读），正文永远不落盘：打开弹窗只标记已读，**点生成时才按需抓正文**，内存里最多保留最近 40 篇页面文本供生成复用，重启即清。

**聚合而不是分栏。** 每个源独立抓取（12 s 超时、单源失败只少几行），按 URL 去重、按 `publishedAt` 倒序合并；每个源每轮 `cap` 20 条，防止一轮被高产源刷屏；历史由时间线累积，详见上一段。添加页因此是一条时间线，而不是"按源分组"的目录——列表本身就是"最近有什么可以练"。话题筛选是客户端的第二层，等级是用户的选择，三者互不打架。

**等级靠确定性校验，不靠模型自评。** 每个等级在 `lib/rewrite.js` 的 `CEFR_PROFILES` 里有一份完整档案：**定义（能做什么）+ 句法要求 + 词汇要求**。这份档案有两个读者——提示词原样带上它（`buildExercisePrompt`），弹窗展示同一份定义（测试钉住两者一致）；提示词明确"等级由句法结构和词汇等级决定，句子数量只决定练习长度"，6–20 句是篇幅，逐句词数按等级（A1 10、A2 12、B1 15、B2 18、C1 22、C2 24）。生成只调用一次：模型返回标题、逐句英文/中文/given 和 3–4 个英语学习向的 ASK AI 建议问题（语法/词汇/搭配/句型/发音/翻译，引用本文具体词句；禁止作者、来源、插件、练习方法等元问题）；输出先规范化弯引号、括号、分号、破折号、斜杠和 URL（排版习惯，不是等级错误）。`validateRewrite` 在 `{length:false}` 下跳过字数/句数，只卡**最长句/平均句长、从句密度、A1 禁用完成时、长词占比、URL/Markdown、5-gram 重合度**；不合格不重试，返回 `rewrite-failed`（原因随响应返回并写入 client.log），由页面用 toast 报错，文章留在列表里。不随附 Oxford 3000 / EVP（版权），所以词汇等级是"近似"而不是"考纲"。

**一次添加只花一次模型调用。** 同一个回复就是整份练习：标题、逐句英文/中文/given、以及给 ASK AI 的 3–4 个英语学习问题；没有第二遍翻译，也没有“再试一次”的重复计费。同一个 `(原文 URL, CEFR)` 只对应一个练习 id，重复添加是覆盖而不是堆叠。

**添加弹窗是一张文章卡 + 一个等级下拉框。** 点 `+` 打开「将文章生成听力练习」：顶部卡片是列表里已有的标题、两行摘要、favicon + 域名 + ↗ 原文链接；下面是「选择等级」的**系统原生 `<select>`**（A1–C2，默认"我的等级"，选项文本 `等级 · 名称`），再下面是所选等级的定义；定义下方是可展开的 TTS 选项（音色 + 语速，默认取当前 profile 设置，改动经 `onSettings` 持久化）；底部左侧写明「采用 <模型名> 生成」（模型名来自 Host 当前会话、无需额外 API Key），右侧是「生成 B1 短文」，右上角关闭。打开弹窗只把文章标为已读，**不抓正文**；确认生成时才抓全文（内存复用），失败由生成接口返回 `no-article-text` 让页面提示，而不是用预览失败提前禁用按钮。确认后弹窗立即关闭，行内 `+` 换成转圈 spinner，其他行暂时不可点；生成完成时行变对勾，并在 `shell.overlay` 上弹出**系统级 toast**「已加入练习簿：…」。

**toast 为什么自己做而不是 `require` 系统组件。** DSH 的 `Toast` 来自 `@deepseek-ai/dsh-client-ui-primitives`，只存在于编译后的 Web 应用里，没有暴露给 lazy-CJS 插件；插件的 `require` 只有 `react`。官方插件（open-in-app、plugin-manager）也是各自在 `shell.overlay` 里渲染同一个视觉。所以这里同样挂在 `shell.overlay`、用同一套 overlay/label token 复刻位置与行为（底部居中、成功态对勾、2.8 s 自关、点击关闭），而不是去读别人的 DOM 或伪造一个半透明提示。

**列表类页面列宽跟 DSH 插件列表走，练习页保持全屏。** 首页、添加页等列表类页面共用 `.dsh-de-page` 上的 `--de-page-max: 960px` 与 `--de-page-inset: clamp(24px, 4vw, 48px)`（≤767px 为 20px），和插件管理器页 `.page > * { max-width: 960px }` + `--plugin-page-inset` 一致；**听写练习页是例外**——顶栏、答题区、底部条全宽铺满面板，只有句子/反馈列（780px）和结束页正文列（60%/720px）限宽，因为这两处限宽是阅读和输入手感的一部分，不是版式对齐。

**浅色主题里 `--dsw-alias-bg-layer-2` 等于白色。** DSH 的 `design-platform.css` 把 light 的 layer-1/2/3 都映射到同一个白值，所以任何「用 layer-2 做卡片灰底」在日间模式下都会消失。插件因此定义了自己的 `--de-fill`（文字色 7% 混合）与 `--de-fill-strong`（12%）：浅色下是 `#ededed` 左右的灰块，深色下是提亮一档的卡片，两边都能看见；统计卡、弹窗原文框、等级定义框、话题 chip、hover 底色、进度槽都改用它。

**词框宽度是 `ch`，所以字体必须是等宽的。** 输入框的宽度按单词字母数设置（`width: Nch`），只有等宽字体下 `ch` 才等于字符宽；文章听写页显式使用 `ui-monospace / SFMono-Regular / Menlo / Consolas`，不随页面正文的字体走，短词（如 “am”）不会被截断。

**输入框里的灰点就是字符格。** 每个可听写词按 `unit.plain.length` 渲染同样数量的 `.dsh-de-dot`，绝对定位在输入框后面（`inset: 2px 0 8px`，每格 `1ch`，点 2×2px，`currentColor` + `opacity: .1`）；已输入字符数之前的点设 `data-hidden` 隐藏，退格会恢复。半填状态让输入左对齐，剩余点落在右侧空白格；全词填满后等宽字体铺满整个 `Nch`，点全部隐藏。given 词不渲染点。结果页也一样：`.dsh-de-result-chip`、`.dsh-de-result-given`、`.dsh-de-result-punct` 都是 30px / `line-height: 1.25` / `2px 3px` 垂直内边距，字体、行盒和基线一致。

**听写得分只有两个一级维度：拼写准确度 × 听辨流畅度。** 拼写准确度来自逐词检查次数和提示（1 / 0.6 / 0.3 / 0.1，再乘 0.25 / 0.6 / 0.8 / 1.0），given 词和标点不计；空输入只标红、不算 attempts，同一错误重复提交只算一次。听辨流畅度 `C = 100 × L × E`：L 是输入期重听因子（每句 1 次内免费、最低 0.8），E 是效率因子（当前每词用时对比本人同等级最近文章的中位数，至少 3 篇样本，最低 0.85）。最终 `A × C / 100`，结束页和首页展示。

**单句完成后的声音是“再听一遍”。** 检查通过时不再播放上扬的成功音，而是调用 TTS 重播当前句子（离开结果页或继续下一句时取消）；检查不通过时播放低音错误音。整篇完成仍保留 congrats。

**声音可视化不重新路由音频。** 练习页底部的多色渐变（种子色 #A365F2 / #45CEB1 / #DACF5C，含一个紫+青混合的过渡层）只在朗读时出现，由 `tts.analyser()` 的低频能量驱动 CSS 变量（每 ~33 ms 写一次，不触发 React 重渲染）。分析用 `HTMLMediaElement.captureStream()` 把音频复制进一个 AnalyserNode，**不**用 `createMediaElementSource`：后者会把声音接管到一个可能处于 suspended 的 AudioContext，自动朗读时会直接静音。浏览器没有 `captureStream`、或走系统语音时，退回合成脉冲，视觉节奏仍在。`prefers-reduced-motion` 下光斑不位移。

**练习 id 是文章 URL 的哈希。** 源列表行 id 与生成的练习 id 都是 `sha1(url).slice(0,12)`，所以添加页可以先按 id 判断“这篇已在练习簿里”，不必依赖 URL 字符串完全一致；历史练习（旧的 `sha1(url#cefr)` id）回退按 `source.url` 匹配。副作用是同一篇文章再生成会覆盖同一个练习文件——UI 在已加入时本来就不给 `+`，所以这符合“一篇练习”的产品语义。

**空练习簿会先得到一篇能读懂的说明。** 新 profile 第一次启动时 seed 一篇内置 A2 练习：Fei 用 15 句、113 个词介绍自己、这个插件解决什么问题、以及怎么开始第一次听写。它就是一份普通 unit（同样的 `sentences/zh/questions/source` 形状），所以进度、TTS、重练、ASK AI 全都不用特判；`.first-practice-seeded` 标记表示这个 profile 已经领过，删掉练习也不会再被塞回来；已存在的内置 unit 会在启动时把 questions 刷新成当前的学习问题，但不动句子和进度。seed 只在 Host 启动时跑一次，测试通过 `DSH_DICTATION_SEED=off` 关掉。

**移除不是删除来源。** 练习行菜单的「移除练习」把 unit 和 progress 从 `articles/` 删掉，但先把标题、等级、`source`（含原文 URL / provider / licence）和生成/移除时间写进 `archive/`。学习档案页列出这些记录；「重新生成」按归档等级重新抓原文并走同一次生成，内置首练则直接恢复 unit。只有重新生成成功才删归档记录——失败时源还在，可以再试。

**搜索框同时是自定义文章的入口。** 列表顶部一条输入：普通文字变成「<search> 文字」建议，点击按标题过滤；合法 URL 变成「+ url」建议，Host 先抓页面（拒绝 localhost/内网，避免把 Host 变成 SSRF 代理），提取标题和正文、缓存正文，返回一个临时 `provider: custom` 行，随后复用同一个等级弹窗和单次生成流程。自定义行只在内存里，不写进 RSS 时间线；生成的练习照常入库。

**原文链接跟着练习走。** 生成练习时把源文章的 URL 一起写进 `unit.source.url`（旧练习回退到 `link`），练习页和整篇结束页的标题后面都有一个 ↗ 图标链接，新标签页打开源站。图标库里没有 external-link 语义的图标（最近的是 `<unlink>`/`<sync-outlined>`，语义都不对），所以用现有的右箭头 `ArrowRightGlyph` 旋转 -45° 当作外链箭头，没有新画路径；之后补一个专用的 `<external-link>` 可以直接替换。

**菜单是 icon-studio 的表面，不是一个裸 `<details>`。** 首页两个 `⋮`（页面菜单和练习行菜单）共用同一套面板：9px 圆角、4px 内边距、28px 行高、细边框 + `0 10px 28px` 阴影，普通项 `label-secondary`、悬停 `bg-layer-2` + `label-primary`，危险项（移除练习）用 `state-error`。行菜单锚在**整行下方**（`.dsh-de-menu-row { position: static }`，由行做定位祖先），不再是 22px 的 `⋮` 按钮下方，所以不会盖住标题和句数；列表悬停只做透明度高亮、不做缩放，菜单不会跟着指针漂。原生 `<details>` 不会因点击别处而关闭，页面里加了一个 `pointerdown` 捕获监听，把任何 `details.dsh-de-menu[open]` 收起。

**favicon 由 Host 代理，不让页面直连源站。** 添加页每行标题前的小图标是源 favicon：Host 取源主页、读 `<link rel="icon">`（NOAA/NIST/PLOS 都在自定义路径，直接猜 `/favicon.ico` 会 404）、回退 `/favicon.ico`，把字节缓存到 `favicons/` 再以同源路由返回。这样页面不碰第三方域、不触发 CSP，也不把用户的请求暴露给每个源站；7 天后才刷新。取不到时用来源首字母的方块兜底——图标库里目前没有 globe/rss/link 这类“站点”图标，所以没有自己画路径。

**等级徽章统一为 CEFR。** 首页练习行、听写页顶栏、整篇结束页都显示 `A1/A2/B1/B2/C1`（A 紫、B 绿、C 黄），不再有 `L1/L2/L3`；旧练习没有 `cefr` 时按标题里的 `– level N` 映射成 A2/B1/B2，界面不会出现两套等级。

**等级弹窗是独立组件。** `LevelDialog` 只管"一个等级下拉 + 我的等级 + 确认/取消"，页面只管"哪一行被点了"；`Esc`、遮罩、取消关闭，生成中确认按钮禁用。**弹窗里写的是等级定义（A1 入门 / A2 初级 / B1 中级 / B2 中高级 / C1 高级 / C2 精通 + 该等级能做什么），不是词数**：CEFR 描述的是能力，词数和句长只是 Host 后面用来验收改写的内部门槛，不该出现在选择器上。确认时把等级写进 `profile.settings.cefr`，所以下一次点 `+` 默认就是它——这就是"用户自己的等级"落地的位置。行尾的对勾表示"这篇已经在练习簿里"，悬停会说是哪一级加的；同一篇要换一级加，需要先删（当前没有删除入口，刻意留到下一轮）。

**许可证随内容走。** 练习单元里存 `source:{provider,label,url,license,attribution}`，结果页不再单列来源行，原文链接在标题栏。WHO 的内容按 CC BY-NC-SA 3.0 IGO 使用：署名、非商业、衍生同许可；这条要写进 README，不能假装改写后就脱离了原许可。

**旧数据不迁移。** 旧练习没有 `cefr`/`source`：首页按标题里的 `– level N` 映射成 A2/B1/B2 显示，复盘页不显示来源行。等它们重练或删除。

## 当前产品方向（2026-11，v0.46）

**首页 = 练习簿。** 按 `design/home.png` 实现：标题 + 一句话说明，右上角是黑色「添加练习」按钮和 `⋮` 菜单；五个统计卡（累计耗时 / 听写文章 / 平均得分 / 词汇覆盖 / 连续坚持）；下面「练习(N)」列表，每行 = 等级徽章（L1 紫 / L2 绿 / L3 黄）+ 标题 + 右侧「未开始 / 进行中（黄） / 已完成 · 已打/总句」，完成项有分数时显示绿色「综合分 · 进度」+ 黑色圆形箭头 + `⋮`（移除）。

**加载是骨架屏，分类栏是固定的。** 时间线第一次拉取时显示 8 行骨架（圆点 / 标题条 / 元信息条 / 加号），分类栏不依赖数据先出现（全部 + 六个分类，计数为 0），数据回来再替换；这样空列表不会只剩一句「正在读取文章…」。

**添加页 = 选文章。** 按 `design/add.png` 实现：`←` + 「添加文章到练习簿」+ `↻`；每行 = 灰点 + 标题 + `6 sentences , 30 words, 5d ago`（数字加粗）+ 浅灰圆形 `+`；底部「加载更多」。

**练习簿就是「已生成的文章」。** 没有第二份列表：`/articles/saved` 一个路由同时供首页的行、行进度和五个统计卡使用。

这一版的设计取舍：

- **统计卡全部从进度文件派生，不落盘新的计数。** `summary` 在 `/articles/saved` 里现场算：耗时 = 各篇 `progress.elapsedMs` 之和；听写文章 = 有 progress 的篇数；平均得分 = 已完成文章「听写得分」的平均值；词汇覆盖 = 去重后的 `plain` 词数；连续坚持仍来自 profile 的 `stats.days`。删掉一篇文章，它的贡献自动消失——数字不可能和练习簿对不上。
- **添加停在添加页，不把人扔进第一句。** 添加页的落点是「把文章放进练习簿」，不是「现在开始听写」；点 `+` 后该行变成绿色对勾，可以接着加下一篇。想练哪篇由首页的行决定。失败时在行上方给提示并保留 `+`，可以重点一次。
- **句数/词数在添加前就算出来。** 拆句是纯规则（`lib/article.js`），所以 `/articles` 直接下发 `sentences`/`words`/`publishedAt`，行里承诺「6 句、30 词」而不是点完才知道。正文不再下发给页面：生成时 Host 再按 link 取一次。
- **标题去掉 `– level N`。** 徽章已经写着 L1/L2/L3，标题再带一遍等于两次；`displayTitle` 只做这一件事，旧标题也因此不用迁移。
- **菜单用原生 `<details>`，不给首页加状态。** 首页是一个纯展示组件（可离线直接调用渲染），`⋮` 的开关交给 DOM；点菜单项时顺手把 `details.open` 关掉。行菜单只有「移除练习」：它把 unit 和 progress 移出练习簿，但先把源和 meta 存进 `archive/`，学习档案页可以用同一篇原文重新生成；逐词记录会随移除一起清掉，统计只反映仍在练习簿里的练习。
- **「加载更多」是真分页。** feed 一次可能给二十来条，首屏 50 条，点一次多 50 条；它不假装在等网络。
- **保持一处英文标题。** 「English Dictation」和设计图一致，两个语言都写死；说明文字、单位、按钮全部走 locale（中文单位沿用图里的 `8.1 h / 10 篇 / 50 % / 200 个 / 40 天`）。设计图里的说明文字是「during the agent is at work」，语法不通；按最新文案落地为「Practice English dictation with short texts between the agent's tasks.」/「Agent工作的间隙，用英语短文练听写。」（首页副标题与插件列表 desc 同一句）。

## 一句话

把练法换成听写：系统念一句；一句 = 一个单元，单元里几道题（一个词 / 短语 / 整句），每个词都有自己的输入框；最后整句默写一次。一次只练一句，练完立刻本地反馈 + AI 复盘，同时生成下一句，点继续进入下一句。

## 做什么

- **听写（单元 + 题）**：一句 = 一个单元；单元里几道题（一个词 / 短语 / 整句）。**每个词一个独立输入框**（宽度 = 字母数），`Space` 跳到下一个框，`Enter` 检查；错了在错词下标红线、焦点回到第一个错词。整句题计分。
- **输入是一排按词拆开的下划线框**：`Space` 跳到下一个框，`Enter` 才检查；**正确弹词卡**（音标 / 词性 / 中文 / 红色底线），**错误给错词标红线并把焦点放回第一个错词**。`Ctrl/⌘+I` 发音、`Ctrl/⌘+;` 在页面顶部浮出答案层。
- **一次一句**：本地反馈 → （并行）AI 复盘 + 下一句 → 继续。没有 10 题一组、没有结算页。
- **打开先 Dashboard**：估算水平、连续天数、今日句数/分钟、上次练习摘要、弱项，然后才开始练。
- **每句一张反馈卡**：第一层本地即时（判定 / 用时 / 错词还原 / 词性着色 + IPA），第二层 AI 复盘（判断 + 一条可用的辨音或拼写规则 + 最多一个重听动作）。
- **滚动评级 C..SSS**：最近 10 句的得分率；连击跨句累加，`f(n)` 加成。
- **自适应**：θ 按答完的一句更新；每 4 句插一句 θ+1 的挑战句。
- **本地档案**：θ、标签掌握度、每次练习摘要、今日/累计、连续天数，全部落在 `~/.dsh/storages/dsh-english-dictation/`。

## 不做什么（P0 边界）

中译英 / 翻译 / 看图说话、固定题数与结算页、自动跳题、社交 PK 排行榜每日任务、云同步多用户、第三方 TTS 服务（Piper / Edge Read-Aloud）/ 音频文件、语音识别与口语评分、课程包与自建材料、agent 工具。

## 为什么这样切

**判定必须本地、必须是规则。** 打字手感依赖「打错立刻红一下、打满立刻可以提交」的即时性，任何网络往返都会把它毁掉。所以输入 → 规则 → 反馈卡全程在浏览器里，`/run/answer` 只在反馈卡已经出现之后才发出。也正因如此，计分函数在 host 与浏览器各有一份：host 是权威（防止客户端报假分），浏览器是即时反馈；`test/run.mjs` 用同一批用例交叉核对，防止两份漂移。

**AI 只出现在两个窄口子。** 出下一句、写复盘。这两处都锚定了确定性输入（θ、弱项标签、最近句子 / 这一句的答案与输入），失败时都如实报错（「这次没生成复盘」+ 重试 / 出题失败 + toast），因此模型慢或挂掉不会污染计分，也不会用预置句子顶替。

**这两处都不要「思考」。** 出题和复盘是格式活，不是推理活；而宿主默认的 reasoning effort 往往是 `high`，思考 token 与正文共用 `maxTokens` 预算，结果 JSON 被截断、解析失败、三次重试全废——页面只看到「出题失败」。所以调用前按模型声明的能力要 `off`（模型不支持就退回宿主默认），`maxTokens` 也留足；这两个预算写死在 `lib/prompts.js`，由 `test/run.mjs` 盯着。

**一个词一个框，`Space` 跳、`Enter` 判。** 一句拆成几道题（词 / 短语 / 整句），每道题的每个词都是一个独立受控 `<input>`，宽度 = 该词字母数（下划线就是「这里填几个字母」）。框与框之间用 `Space` 走，`Enter` 检查整道题；判错时只给错词标红线并把焦点放回第一个错词——用户不用自己找错在哪。没有按键拦截字母，也没有镜像层。

**看答案是一个浮层，不是把答案填进输入框。** 遮罩 + 居中卡片，每个词一块：音标、大字单词、彩色底线、`base（form）：zh` 的语法/中文说明、词性。看完 `Enter`/`Esc` 关闭，**回到本题**（不跳题）：这一题记为「看过答案」，整句题即使打对也按 0 分判定。`base`/`form` 是模型可选提供的（is → be / 第三人称单数现在时），题库兜底时退化为只有中文。

**判对给卡，判错标红并清空。** 判对时显示一组结果（✓ 正确 / 音标 / 大字单词 / 红色底线 / 词性 / 中文），**无边框、不带输入框外观**；卡片自己拿焦点，`Enter`（或点空白处）就进下一题，下一题的框自动聚焦——没有「继续」按钮。判错时给错词标红线、焦点回到第一个错词，内容保留着方便改。

**计分只剩三种「打对了」的差别。** 每屏都必须打对，所以计分不再需要「提交错句」这条路径：整句屏一次对 = Perfect，退格过 = Great，检查失败过再改对 = 过关。只有整句屏看答案是 0。

**反馈卡期间可以继续，但「继续」要等下一句。** 复盘失败不阻塞（规格明确），下一句没就绪也不该阻塞观感，所以卡片底部同时显示「正在出下一句…」；两项都到位才亮「继续」，整体上限 5 秒。

**拆分 = 句子成分。** 模型给出 `chunks`（词下标分组）与 `roles`（主语/谓语/宾语/表语/定语/状语/补语…），host 校验后使用；坏了就退回 `parseChunks`（同样按成分：主谓宾/表/状）。一块成分是一道题，成分里的每个词仍是自己的输入框——和参考产品一致。标点是**印出来的**，不参与输入。

**按词性和语法，不按字数（旧规则，现为兜底）。** `chunkSentence` 的规则：动词连同助动词/否定（`is studying`、`is not`）、系动词 + 形容词（`is happy`）、介词 + 宾语（`for an exam`、`in his room`）、`to + 动词`（`to eat`）；其余单词单独一题，**名词短语不合并**（`my brother` → `my` / `brother`）。模型只提供单词和词性，分组完全由规则决定，所以不会出现「随便两个词凑一组」的奇怪切分，也不会因为模型换了就变。

**为什么一句拆成几道题。** 一整句一打，新手的失败点集中在前半句：还没听清就先想拼写，错了还得在长句里找位置。把句子切成语义词组（`to eat`、`a glass`），每道题只想 1–3 个词，注意力全部还给听音；每题只显示这一组、只念这一组，`Enter` 才走，节奏由用户掌握。最后整句重打，逼一次完整回忆——这才是「听写」。评测只认整句题，脚手架不产生 Perfect、也不污染错题标签，否则会把「辅助后打对」误记成「我拼写没问题」。词组由模型给（它知道语义边界），host 校验覆盖性与顺序，坏的或缺失的用规则推导（`to/a/an/of/in…` 与下一个词合并），保证任何来源的句子都能切。

**每个词一个框，框宽 = 字母数。** 参考产品里一句话的每个词都落在自己的下划线上，当前词高亮。这里把「输入」也拆成同样的粒度：每道题的每个词是一个受控 `<input>`，宽度 = 该词的字母数，`Space` 在框之间移动，`Enter` 检查整道题。判错时不需要用户自己找错：错词标红线，焦点直接回到第一个错词。

**某个框突然打不进字，是最坏的一类 bug。** 所以输入路径里没有「拒绝」这一步：每个框的值就是唯一事实，`input` 事件只同步值，判定只在 `Enter` 时发生。焦点丢失和输入法组词都有可见提示，不会静默失败。

**TTS 的粒度是这一题。** 每次念的都是这一题的词或短语本身（`speak('to eat')`），一次独立的合成；整句只在整句题/「整句」按钮上作为一整句合成。三级都是「文本 → 音频」现场合成（宿主 Edge-TTS、本地 macOS `say`、系统 `speechSynthesis`），根本不存在「从整句录音里剪一段」——这里把这一点固定下来：短语题绝不拿整句文本去截。

**声音优先用 Edge 神经网络音色。** Host 调本机 `edge-tts` 合成 MP3，落盘缓存；Edge 不可用/失败时回退本地 macOS `say`（WAV），再失败回退系统 `speechSynthesis`。不需要 API Key；代价是 Edge 需要 `edge-tts` 这个 Python 包，且合成走网络。

**语音按钮念本题的词/短语。** 每题只有一个词或短语，所以按钮直接合成这一题的文本；短语题另有「整句」按钮听上下文。整句题上按钮就是整句。

**只做修饰键快捷键。** 页面本身就是键盘输入区：单字母快捷键会把那个字母从输入里吞掉（`R` 曾经如此，`red` 打不出来）。所以只保留参考产品那套修饰键组合（`Ctrl/⌘+I` 播放发音、`Ctrl/⌘+;` 显示答案），外加 `Enter` / `Tab` 检查——`Tab` 不是可输入字符，`Enter` 在输入框里就是「提交」。`shortcutOf` 是纯函数，没有 Ctrl/⌘ 就返回 null，单字母永远进输入框。

**一个词一根下划线，长度 = 这个词的字母数。** 输入框不再是一条整线：`to work` 画两根线（2 格 + 4 格），中间留一个空格；整条宽度 = 本屏字母数 + 词间空格。这样「这里要填几个字母」是明示的——下划线本身就是提示，用户能数出词长。代价是暴露了词长（早期的规格要求隐藏），这是按产品要求改的：宁可给长度提示，也要让输入框的结构和实际打字完全对应。实现上用等宽字体 + `ch` 单位：输入框宽度 `Nch`、每根下划线 `len ch`、词间 `gap: 1ch`，所以打的字和线严格对齐。

**「不会输入」必须有出路。** 听写最现实的失败不是打错，是卡在一个词上不知道拼法。现在的出口全是按钮：输入框下方常驻「看答案」（整句显示、本题 0 分、连击归零）；**7 秒没有输入**浮出「卡住了？」面板（放慢再听一遍 / 听整句 / 看答案）；语音区随时可以「整句」。分屏让这个词只出现在一屏里——卡住时放弃的成本也就是这一屏，而不是整段。

（早期版本有一个「跳过这个词，整句仍算过关 40 分」的 `Tab` 快捷键，随「不要快捷键」的要求一起移除了；host 的 `skippedWords` 能力保留着，想以按钮形式放回来随时可以。）

## 话题词集模型（0.21）

练什么不再由用户选等级决定，而是由**话题词集**决定：每个话题声明自己的等级（A1–B1+）、内容词与搭配、交际功能与语法轮换。打开插件就是话题列表，点一个直接练——没有题库生成等待、没有自定义语料、没有等级设置。

- **难度靠词集，不靠模型**：生成时内容词必须落在该话题词集内（≥95%），句子长度 5–10 词；模型自报的难度不再参与判断。
- **多样性靠 spec 调度**：每句从「最少练过的功能 × 下一个语法轮换 × 未练/错过的词」里选一个组合，配合句间去重（n-gram <0.2、开头三词不重复）。
- **进度靠词覆盖**：记录每个词的练过/答错次数，卡片显示「已练 120/180 词 · 掌握 76%」——比「第 20/100 句」更接近"会不会"。
- **无限练习**：有限词集 + 组合调度 + 错词复现，题库不落盘也不枯竭；生成过的句子缓存为当前句，切 tab 回来直接续上。

## 关键取舍

| 决定 | 理由 |
|---|---|
| 不用 esbuild，`lib/client.js` 直接是 lazy-CJS 产物 | 少一个构建环节和一份产物漂移；纯规则用测试交叉核对更可靠 |
| 复盘一次性返回而不是逐 token 流 | 规格的路由表里 `/run/answer` 同时返回 `report` 与 `next`，5 秒上限；拆 SSE 会破坏这个契约 |
| 不预取：点「继续」才写下一句 | 写一句是唯一会让人等模型的时刻，也就该由人按一下决定它何时发生；代价是「继续」要等 1–2 秒（关掉思考后），换来的是句子永远紧跟当前 θ，也不会在后台悄悄烧 token |
| 不带句子库 | 句子只有两个来源：模型当场写，或（接入后）外部语料 + 模型改写。插件不内置任何现成句子，失败就报错 + 重试，不用替身 |
| 页面状态放在 React 之外 | 主面板是 keyed slot，切 tab 会卸载组件。`pageMemory` / `practiceDraft` 记住屏幕与草稿（题目、步骤、已打的字、用时、判定卡），回来就回到原处；服务端的 `activeRun.current` 是最后一道保险 |
| 响应丢了就向上游确认，别让学习者重来 | 页面等不到任何响应时先调 `/run/start`：它会直接返回这一轮已经写好的句子（不调模型）。请求死在半路和服务端拒绝看起来一样，但前者是可恢复的 |
| 页面等宿主，而不是相反 | 页面侧 45 s 只是防请求卡死；宿主预算 30 s 才有权决定成败。反过来（页面先超时）会把已生成好的句子丢掉 |
| 引用校验放宽到「输入 ∪ 答案」 | 复盘引用正确拼写是合理的；只按输入校验会把好复盘误杀。仍然丢弃查不到的引用并打日志 |
| 词性颜色用 `color-mix(in oklab, label-primary, hue)` | 一个色值同时适配明暗主题，不用写两套 `prefers-color-scheme` |
| 音效用 WebAudio 现场合成 | 不引入二进制音频文件，体积 0 |
| 档案加密写（临时文件 + rename） | 每答一句就落盘，杀进程不能留半截 JSON |
| 额外加 `/profile/settings`、`/profile/reset`、`/tts/status`、`/audio` | Dashboard 的发音来源/音色/语速需要落盘，朗读需要一个合成入口；reset 是「重新自评」和维护时的逃生口 |
| Edge-TTS + 本地 `say` + 系统语音三级，Edge 优先 | 神经网络音色自然；本地 say 负责断网/Edge 失败，系统语音最后兜底 |
| 语速在浏览器用 `playbackRate` 施加 | `/v1/tools/tts` 没有 speed 参数；变速不变调，和系统语音的 `utterance.rate` 共用同一个滑杆 |
| 只有修饰键组合 + `Enter`/`Tab` 检查，没有提交按钮 | 页面本身就是键盘输入区：单字母快捷键会吞字母（`R`）；`Tab`/`Enter` 不是可输入字符，用它们检查不需要鼠标 |
| 分屏输入：一屏一个词/短语，`Enter` 才走；只有整句屏计分 | 一屏一两个词才把注意力留给听音；脚手架阶段的错误不代表真实回忆能力，算进分数会把「辅助后打对」误记成掌握；计时与重播仍整体统计 |
| 每屏只显示本屏的输入框，不显示整句 | 「一屏一个单词」就是字的密度；显示整句等于把答案摊开 |
| 一个词一个独立输入框，`Space` 跳框、`Enter` 判 | 「一个词一个框」让词与词互不干扰，也自然对齐了词长提示；判错只标错词并回焦，改起来有方向 |
| 判错不清空内容 | 新版交互要求「标红线 + 聚焦第一个错词」；清空会让人重新输一遍，反而更慢 |
| 判对弹词卡 | 把这一组词音标/词性/中文过一眼，等于顺手记一个词块；也是「对了」的正反馈 |
| 判错标红 + 5 秒清空 | 错误要看得见但不能把人困住：红一下，清空，重打 |
| 比较时忽略空格与大小写 | 空格是排版不是知识；为了一个空格标红只会让人恼火 |
| 必须打对才能过屏 | 组词屏是脚手架，打对才说明听清了；整句屏计分，打对才有分 |
| 快捷键只有修饰键组合 | 单字母必须能打出来；修饰键组合不会和输入冲突 |
| 输入框长度只由词数决定 | 让「这句有 8 个词」一眼可见（听写的标准提示），同时不泄露每个词多长 |


## 一屏的状态机

```
一排按词拆开的输入框 ──Space 跳框──▶ 按 Enter 检查
        ▲                              │
        │                    正确 ─────┤──▶ 词卡（短语题）──Enter──▶ 下一题（首框自动聚焦）
        │                              │
        └── 改完再按 Enter ◀── 错误 ───┘（错词标红线，焦点回第一个错词）
```

整句屏没有词卡：正确 → 判定（Perfect / Great / 过关）；看答案 → 0 分。输入期间不显示任何对错。

## 计分

每道题都必须检查通过才进下一题，所以计分只看整句题「第几次检查通过、有没有退格」；不存在「提交了错句」的情形（host 仍保留 `!matches → pass` 的兜底）。

## 里程碑

M0 垂直切片（可装、Dashboard、写死 5 句也能练完、TTS、打字、反馈卡、连击、滚动评级）→ M1 内容管线（`ctx.llm.stream` 单句 + 校验重试降级）→ M2 逐句复盘（span 校验、失败降级）→ M3 档案 → M4 打磨（词性着色、IPA、音效、词级重播、语速、暗色）。

本轮一次交付了 M0–M4（规格 §17 建议先停在 M0 让人试手感；实际把整条闭环做完再交付，因为 AI 部分与手感解耦，改起来不牵连）。手感部分如果不对，最可能需要改的是：下划线输入框的宽度与字号、词卡的信息量（音标/词性/中文的取舍）、标红与 5 秒清空的节奏、分屏的粒度（词组切分）、整句屏反馈卡的信息密度——这些都在 `lib/client.js` 的 CSS 与 `Practice` 组件里，不碰 host。
